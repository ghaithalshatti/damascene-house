# 🍽️ QR Menu — منيو إلكتروني للمطاعم بدون باك اند

قالب جاهز لمنيو مطعم يُفتح بمسح رمز QR على الطاولة. موقع ثابت (HTML + CSS + JavaScript) يُستضاف **مجاناً** على **GitHub Pages**،
مع لوحة إدارة لصاحب المطعم، و**طلبات مباشرة اختيارية** عبر **Firebase** (خطة Spark المجانية)، بدون أي سيرفر أو تكلفة استضافة.

القالب عام: لكل مطعم نسخة مستقلة من هذا المستودع بإعداداته وهويته الخاصة.

## الميزات

**للزبون (المنيو)**
- عربي فصحى + إنكليزي (أو لغة واحدة)، مع اتجاه RTL/LTR تلقائي.
- تصميم متجاوب لكل الشاشات: من الموبايل الصغير (320px) حتى الشاشات الكبيرة (قائمة الأصناف تصبح شريطاً جانبياً).
- 12 ثيماً احترافياً بتدرجات لونية + 4 أنماط تصميم (كلاسيكي / زجاجي / تطبيق موبايل / مجلة فاخرة)، يُختار منها في صفحة الإعداد.
- بحث ذكي يتجاهل الهمزات والتشكيل، تبويبات أصناف تتبع التمرير.
- تفاصيل الوجبة: صورة، وصف، أحجام بأسعار مختلفة، وسوم (الأكثر طلباً، جديد، حار، نباتي).
- سلة طلب: كميات، ملاحظة لكل وجبة («بدون بصل»)، تعديل وحذف.
- **بدون Firebase:** زر «اعرض الطلب على النادل» يعرض شاشة واضحة برقم الطاولة.
- **مع Firebase:** «أرسل الطلب» + «نادِ النادل» + «اطلب الحساب»، ومتابعة حالة الطلب (تم الاستلام ← قيد التحضير ← جاهز).
- زر «طلباتي» محفوظ على موبايل الزبون لهذه الطاولة فقط، ويُمسح تلقائياً عند «تم الدفع» أو بعد 4 ساعات من آخر طلب، فالزبون التالي على الطاولة يبدأ من الصفر.
- الوجبات غير المتوفرة تختفي تلقائياً.

**لصاحب المطعم (لوحة الإدارة)**
- دخول بكلمة سر واحدة، يعمل من الموبايل.
- إضافة وتعديل وحذف الوجبات والأصناف، ترتيب بالسحب، إخفاء/إظهار بكبسة.
- رفع صور تُضغط تلقائياً (WebP).
- معلومات المطعم: الشعار، الغلاف، الهاتف، العنوان، الدوام، الخريطة، حسابات التواصل.
- تبويب «طلبات اليوم»: عدد الطلبات، المبيعات، متوسط الطلب، الأكثر طلباً، الطلبات حسب الساعة.
- رابط القائمة للمشاركة + مولّد رموز QR للطاولات + تغيير كلمة السر.
- كل حفظ يُنشر تلقائياً ويظهر للزبائن خلال دقيقة تقريباً.

**للطاقم (شاشة الطاقم)** — تتطلب Firebase
- استقبال لحظي للطلبات والنداءات وطلبات الحساب على أكثر من جهاز معاً.
- تنبيه صوتي واهتزاز، عدّاد في عنوان التبويب، الشاشة لا تنطفئ.
- فلاتر (طلبات / نداءات / حساب)، حالات الطلب، و«تم الدفع» مع حساب مجموع الطاولة.
- تبويب **«سجل اليوم»**: كل طلبات اليوم (حتى المنتهية والمدفوعة) مجمّعة حسب الطاولة، مع وقت كل طلب ومحتواه، ومجموع كل طاولة، والمدفوع وغير المدفوع، وعدد النداءات. يبدأ من جديد كل يوم عند منتصف الليل.

## الصفحات والروابط

| الصفحة | الرابط | لمن |
|---|---|---|
| المنيو | `/` | الزبون (رمز QR عام، فيسبوك، خرائط Google…) |
| منيو طاولة | `/?t=5&k=xxxx` | الزبون عبر QR الطاولة |
| لوحة الإدارة | `/admin/` | صاحب المطعم |
| شاشة الطاقم | `/staff/` | النادل / المطبخ / الكاشير |
| الإعداد | `/setup/` | المطوّر فقط |

**معاملات الرابط:**

| المعامل | المعنى |
|---|---|
| `t=5` | رقم الطاولة (يظهر في المنيو وعلى الطلب) |
| `k=xxxx` | مفتاح الطاولة السري (يمنع الطلبات الوهمية؛ يُضاف تلقائياً عند توليد QR مع Firebase) |
| `preview=1&skin=cafe&primary=%23C0392B&style=glass` | معاينة ثيم/لون/نمط دون تغيير الإعدادات (للعرض على صاحب المطعم) |

أسماء الثيمات لـ `skin`: `classic` · `midnight` · `fresh` · `minimal` · `street` · `cafe` · `ocean` · `heritage` · `ember` · `rose` · `olive` · `royal`
ونمط التصميم بـ `style`: `classic` · `glass` · `app` · `magazine` (مثلاً `&style=magazine`)

## كيف يعمل بدون باك اند

```
الزبون ──قراءة──▶ GitHub Pages (index.html + data/*.json + images/)
صاحب المطعم ──حفظ──▶ GitHub API (commit مباشر على المستودع) ──▶ Pages يعيد النشر (~1 دقيقة)
الزبون ──طلب/نداء──▶ Firebase Firestore ◀──لحظياً── شاشة الطاقم
```

- **المنيو والإعدادات** ملفات JSON داخل المستودع. لوحة الإدارة تعدّلها عبر GitHub API بـ commit واحد لكل حفظ.
- **الطلبات** فقط تمر عبر Firestore (لأن GitHub Pages لا يستقبل بيانات من الزبائن).
- لا يوجد أي سيرفر، ولا اعتماد على CDN خارجي (الخطوط والمكتبات محلية).

## تجهيز مطعم جديد خطوة بخطوة

> الترتيب مهم: **GitHub ← Firebase ← صفحة الإعداد ← طباعة QR**

### 1) GitHub: رفع الكود
1. أنشئ مستودعاً **Public** فارغاً (بدون README) باسم المطعم، مثلاً `damascene-house`.
   أو من هذا المستودع: **Use this template ← Create a new repository**.
2. إذا رفعت يدوياً:
   ```bash
   cd restaurant
   git init
   git add .
   git commit -m "init"
   git branch -M main
   git remote add origin https://github.com/USERNAME/REPO.git
   git push -u origin main
   ```

### 2) GitHub Pages: تشغيل الموقع
- المستودع ← **Settings ← Pages ← Build and deployment**
- Source: **Deploy from a branch** ← Branch: `main` ← Folder: `/ (root)` ← **Save**
- بعد دقيقة تقريباً: `https://USERNAME.github.io/REPO/`

### 3) GitHub Token: صلاحية الحفظ من الموقع
افتح مباشرة: `https://github.com/settings/personal-access-tokens/new`
(أو: Settings ← Developer settings ← Personal access tokens ← **Fine-grained tokens** ← Generate new token)
- **Token name:** اسم يعرّفك به، مثلاً `damascene-house-menu`
- **Expiration:** مدة الاشتراك مع المطعم (مثلاً سنة)
- **Repository access:** Only select repositories ← اختر مستودع المطعم (يمكن اختيار أكثر من مستودع لنفس الـ token)
- **Permissions ← Repositories ← Add permissions ← Contents:** Read and write
  (`Metadata: Read-only` تُضاف تلقائياً وهي إلزامية — اتركها؛ تبويب Account يبقى 0)
- **Generate token** ← انسخه بزر النسخ فوراً (`github_pat_…`) — يظهر مرة واحدة.

> ⚠️ ليست صفحة **GitHub Apps**؛ المطلوب **Personal access token**.
> ⚠️ **Regenerate** أو حذف الـ token يُبطل القديم فوراً ← افتح صفحة الإعداد وانشر بالـ token الجديد مع كتابة كلمة سر صاحب المطعم (يمكن نفسها)، وإلا لن يستطيع المدير الدخول.

### 4) Firebase: الطلبات المباشرة (اختياري)
بدونها يعمل كل شيء ما عدا: إرسال الطلب، نداء النادل، طلب الحساب، شاشة الطاقم، وطلبات اليوم.

1. **console.firebase.google.com ← Create a project** ← اسم المشروع ← **أوقف Gemini in Firebase** و**Google Analytics** (لا حاجة لهما).
2. **Databases & Storage ← Firestore ← Create database**
   - Edition: **Standard**
   - Database ID: اتركه `(default)` · Location: **eur3 (Europe)** أو أقرب منطقة أوروبية — لا يمكن تغييره لاحقاً (إن لم تظهر القائمة: حدّث الصفحة أو جرّب نافذة خفية أو VPN لهذه الخطوة فقط)
   - **Start in production mode** ← Create (تجاهل Scheduled backups)
   - لا تضغط Start collection: الموقع ينشئ `orders` و`tables` بنفسه.
3. **Security ← Authentication ← Get started**
   - Sign-in method ← **Email/Password** ← Enable (اترك Email link مطفأً) ← Save
   - Users ← **Add user**: إيميل **حساب مدير المطعم** + كلمة سر (مثلاً `staff@damascene.com`) — الإيميل لا يلزم أن يكون حقيقياً. حسابات النُدُل تُضاف لاحقاً من لوحة المدير (لا من هنا)
   - Settings ← **Authorized domains ← Add domain**: `USERNAME.github.io`
4. **Project settings ⚙️ ← General ← Your apps ← Web `</>`** ← App nickname مثلاً `menu` ← **لا تعلّم Firebase Hosting** ← Register app ← انسخ كتلة `const firebaseConfig = {…};` كاملة ← Continue to console.
5. في **صفحة الإعداد** قسم Firebase: الصق الكتلة + إيميل حساب المدير وكلمة سره + **مدة جلسة الطاولة** (الافتراضي 4 ساعات) ← **نسخ القواعد**.
6. **Firestore ← Rules** ← احذف الموجود (`allow read, write: if false`) ← الصق ← **Publish** (الزر يظهر فوق المحرر بعد اللصق؛ «Develop & Test» ليس المطلوب) ← انتظر دقيقة ← «اختبار Firebase» في صفحة الإعداد يجب أن ينجح.

> لا حاجة لبطاقة دفع ولا لرقم جوال. حساب Google واحد يكفي لكل المطاعم: **مشروع Firebase جديد لكل مطعم**.

### 5) صفحة الإعداد
افتح `https://USERNAME.github.io/REPO/setup/` (الرابط الحقيقي، وليس localhost) وعبّئ الأقسام (التفاصيل في القسم التالي) ثم **حفظ ونشر**.

### 6) رموز QR
في نفس الصفحة، قسم «رموز QR» ← **إنشاء الرموز** ← **طباعة** (أو تحميل PNG لكل طاولة).
اطبعها **بعد** تفعيل Firebase حتى تحمل مفاتيح الطاولات.

### 7) التسليم لصاحب المطعم
- رابط لوحة الإدارة `/admin/` + كلمة سر صاحب المطعم.
- رابط شاشة الطاقم `/staff/` + كلمة سر حساب المدير (يدخل بها المدير بدون اسم مستخدم، ومنها يضيف حسابات النُدُل من «الإعدادات ← حسابات الطاقم»).
- رابط المنيو للمشاركة على السوشال ميديا.

### 8) تجربة نهائية
افتح `/staff/` على جهاز ← ادخل ← «تفعيل التنبيه الصوتي» ← امسح QR طاولة بالموبايل ← أرسل طلباً ← يجب أن يصل فوراً مع صوت.

## صفحة الإعداد (`/setup/`) بالتفصيل

| # | القسم | ماذا تُدخل | ماذا يحدث |
|---|---|---|---|
| 1 | ربط GitHub | owner (اسم الحساب)، repo (اسم المستودع)، branch (`main`)، token | «اختبار الاتصال» يتحقق من صلاحية الكتابة ويحمّل الإعدادات الحالية من المستودع. لا يكتب شيئاً. |
| 2 | الثيم والألوان | نمط التصميم (4 أنماط) + أحد الثيمات الـ12 + لون العلامة | معاينة مباشرة بإطار موبايل تتحدث فوراً. |
| 3 | هوية المطعم | الاسم، العبارة التعريفية، الشعار، الغلاف | — |
| 4 | التفاصيل | اللغات (عربي+إنكليزي / عربي / إنكليزي)، اللغة الافتراضية، العملة، الهاتف، العنوان، الدوام | الحقول تُعرض حسب اللغات المختارة. |
| 5 | الميزات | تفعيل سلة الطلب للزبون | عند إيقافها يصبح المنيو للعرض فقط. |
| 6 | Firebase | الصق `firebaseConfig`، إيميل حساب المدير، كلمة سره، **مدة جلسة الطاولة** (ساعات، 1–24، الافتراضي 4، ويظهر المحفوظ عند الفتح) | القواعد تُولَّد تلقائياً بإيميل المدير ومدة الجلسة — **غيّرت المدة؟ انسخ القواعد وانشرها في Firebase من جديد**. «اختبار Firebase» يسجّل الدخول ويتأكد. **كلمة السر لا تُحفظ.** |
| 7 | كلمة سر صاحب المطعم | 10 أحرف على الأقل، حروف وأرقام | إلزامية عند أول نشر. بعدها **اتركها فارغة للإبقاء على الحالية** — تعديل الثيم أو أي إعداد لا يحتاجها. تُطلب فقط إذا تغيّر الـ token (اكتب نفس كلمة السر). |
| 8 | القائمة الابتدائية | «ابدأ بقائمة فارغة» | يحذف البيانات التجريبية عند النشر. |
| 9 | رموز QR | عدد الطاولات، من طاولة/إلى طاولة، رمز عام | طباعة A4 أو PNG. |

**عند «حفظ ونشر»** يُنشأ commit واحد يحتوي:
- `data/config.json` — كل الإعدادات (بما فيها owner/repo وإعدادات Firebase العامة)
- `data/auth.json` — الـ token **مشفّراً** بكلمة سر صاحب المطعم
- `images/brand/…` — الشعار والغلاف إن وُجدا
- `index.html` — اسم المطعم ووصفه وصورة الغلاف/الشعار في وسوم المعاينة (og)، فيظهر الرابط بشكل جميل عند مشاركته على واتساب وفيسبوك. لوحة المدير تحدّثها أيضاً عند تعديل معلومات المطعم.
- `data/menu.json` فارغ إذا اخترت «ابدأ بقائمة فارغة»

> صفحة الإعداد لا تحفظ الـ token. عند فتحها لاحقاً أدخله من جديد.
> **مطعم منشور:** الحفظ يحتاج الـ token دائماً، وبدونه تظهر رسالة «لم يُحفظ شيء». صفحة الإعداد تقرأ آخر إعدادات من المستودع مباشرة، فبعد الحفظ والتحديث تظهر اختياراتك فوراً (الزبائن يرونها بعد ~دقيقة).
> **نسخة غير مربوطة بعد** (owner/repo فارغان): الحفظ بدون token يخزّن في المتصفح فقط للتجربة.

## دليل صاحب المطعم (`/admin/`)

| التبويب | الاستخدام |
|---|---|
| **الوجبات** | ➕ وجبة جديدة · اضغط الوجبة للتعديل · المفتاح الأخضر = متوفرة/مخفية · ⠿ اسحب للترتيب |
| **طلبات اليوم** | إحصاءات اليوم/أمس (يطلب كلمة سر حساب المدير مرة واحدة على الجهاز) |
| **الأصناف** | إضافة/تعديل (اسم + أيقونة) · ترتيب بالسحب · لا يُحذف صنف فيه وجبات |
| **معلومات المطعم** | الهوية، التواصل، العنوان، الدوام، رابط الخريطة، السوشال ميديا |
| **الإعدادات** | تغيير كلمة السر · رابط القائمة للمشاركة · رموز QR للطاولات · **حسابات الطاقم** (إضافة نادل، كلمة سر جديدة، حذف) |

**في نافذة الوجبة:**
- **الأحجام:** «إضافة حجم» ← اسم الحجم + السعر لكل سطر (صغير/كبير، عادي/دبل). عند وجود أحجام يُقفل السعر الأساسي ويظهر للزبون «يبدأ من» أقل سعر. الحجم الأول هو الافتراضي.
- **الوسوم:** الأكثر طلباً · جديد · حار · نباتي.
- **الصورة:** تُصغّر وتُضغط تلقائياً قبل الرفع، والقديمة تُحذف عند الاستبدال.

كل حفظ = commit تلقائي. يرى صاحب المطعم التعديل فوراً في اللوحة، ويظهر للزبائن خلال دقيقة تقريباً.

## دليل الطاقم (`/staff/`)
- **النادل:** اسم المستخدم + كلمة السر اللذان أعطاه إياهما المدير. **المدير:** يترك اسم المستخدم فارغاً ويكتب كلمة سر حساب المدير. يبقى الجهاز مسجّلاً.
- أول مرة بعد فتح الصفحة: اضغط «تفعيل التنبيه الصوتي» (المتصفحات تمنع الصوت قبل أول ضغطة).
- **طلب:** «بدء التحضير» ← «تم» — الزبون يرى الحالة عنده.
- **نداء نادل:** «تم» بعد الذهاب للطاولة.
- **طلب الحساب:** يظهر مجموع الطاولة ← «تم الدفع» يغلق طلبات الطاولة **وينهي جلسات الطاولة** (الزبون التالي يمسح QR من جديد).
- **فاتورة الزبون:** لما يطلب الزبون الحساب، شاشة الطاقم المفتوحة تكتب **فاتورة الطاولة كاملة** (كل الطلبات غير المدفوعة من كل الموبايلات، بأسعار القائمة) داخل طلب الحساب نفسه تلقائياً، فتظهر عند الزبون خلال ثوانٍ. الزبون لا يقرأ إلا طلب الحساب الذي أرسله. إن لم تكن أي شاشة طاقم مفتوحة يرى فاتورة موبايله فقط.
- **الاستلام:** أول من يضغط «بدء التحضير» أو «تم» أو «تم الدفع» يستلم الطلب ← يظهر للجميع «مع سامر»، وأزرار البطاقة مقفلة على غيره (المدير يستطيع دائماً). تبويب **«طلباتي»** يعرض ما استلمه النادل.
- **بطاقات حمراء مرقّمة:** إذا طلب أكثر من موبايل على نفس الطاولة تصير كل بطاقاتها حمراء وعليها رقم الموبايل (1، 2…)، والجديدة منها تومض حتى يستلمها أحد. إن كان أحدها ليس من الجالسين: **«رفض»**.
- **«رفض»:** يحذف كل طلبات ذلك الموبايل غير المدفوعة على الطاولة من كل الشاشات، ويمنعه من الطلب لهذه الطاولة 3 ساعات.
- الشاشة يجب أن تبقى **مفتوحة** على جهاز واحد على الأقل (تابلت الكاشير مثلاً) لاستقبال الطلبات.

**كلمة سر نادل:** لوحة المدير ← الإعدادات ← حسابات الطاقم ← «كلمة سر جديدة». **كلمة سر المدير:** Firebase ← Authentication ← Users ← احذف المستخدم وأضفه من جديد بنفس الإيميل وكلمة سر جديدة.

## رموز QR والطاولات

### شكل رابط الطاولة
```
https://USERNAME.github.io/REPO/?t=4&k=Ab3xY9qZ
```
| الجزء | المعنى |
|---|---|
| `?` | بداية المعاملات — بدونها يعتبر GitHub أن `t=4` اسم صفحة فيظهر **404** |
| `t=4` | رقم الطاولة (يظهر في المنيو وعلى الطلب) |
| `k=Ab3xY9qZ` | **الرمز السري للطاولة** — بدونه يعمل المنيو لكن **لا يُرسل الطلب** |

### كيف يعمل الإرسال
- **رابط بدون `k`** (أو الرابط العام، أو `?t=4` مكتوب يدوياً): المنيو يعمل بوضع **«اعرض الطلب على النادل»** — الزبون يرتّب طلبه ويُريه للنادل على الشاشة، ولا يُرسل شيء إلى Firebase. ستظهر رسالة «تم تأكيد طلبك» لكن **لن يصل شيء لشاشة الطاقم**.
- **رابط فيه `t` و`k` صحيحان**: تُفتح **جلسة طاولة** ويختفي `k` من شريط العنوان فوراً، ثم يظهر زر **«أرسل الطلب»** وتعمل أزرار «نادِ النادل» و«اطلب الحساب»، ويصل كل شيء لشاشة الطاقم فوراً.
- قواعد Firestore ترفض أي طلب بدون جلسة مفتوحة صحيحة، فلا يستطيع أحد إرسال طلبات وهمية بكتابة `?t=4` من خارج المطعم. التفاصيل في القسم التالي.

### إنشاء الرموز السرية
- تُنشأ عند الضغط على **«إنشاء الرموز»** (في الإعدادات بلوحة المدير، أو في صفحة الإعداد)، وتُحفظ في Firestore في `tables/{رقم}`.
- إنشاؤها يحتاج **تسجيل دخول بحساب المدير**، لأن إنشاء `tables` مسموح للمدير فقط:
  - في **لوحة المدير**: إذا لم يكن الجهاز مسجّلاً بحساب المدير تظهر نافذة تطلب **كلمة سر حساب المدير** مرة واحدة، ويبقى الجهاز مسجّلاً بعدها. إذا أُغلقت النافذة دون دخول **لا تُنشأ البطاقات** ولا يتغيّر شيء.
  - في **صفحة الإعداد**: تُستخدم كلمة السر المكتوبة في قسم Firebase؛ إن كانت فارغة أو خاطئة تظهر رسالة خطأ ولا تُنشأ البطاقات.
  - إذا لم يكن Firebase مُعدّاً أصلاً: تُنشأ البطاقات **بدون `k`** (منيو للعرض + «اعرض الطلب على النادل»).
- **الرمز ثابت لا يتغيّر**: إعادة «إنشاء الرموز» تقرأ الرموز الموجودة ولا تغيّرها، فالبطاقات المطبوعة سابقاً تبقى صالحة. عند إضافة طاولات زِد العدد واختر النطاق (مثلاً من 11 إلى 12) لطباعة الجديدة فقط.

### أدوات البطاقة
- ⬇️ **تحميل PNG** للبطاقة.
- 🔗 **فتح رابط البطاقة** في تبويب جديد (الرابط الكامل مع `t` و`k`) — لتجربة الطلب من الكمبيوتر دون موبايل. لا يظهر في الطباعة.
- **بطاقة عامة** بدون رقم: للباب، الواجهة، الفيسبوك، خرائط Google — تعرض المنيو بدون إرسال طلبات.
- إذا تغيّر رابط الموقع (دومين جديد) يجب إعادة الطباعة.

### تجربة الطلب المباشر
1. افتح `/staff/` وسجّل الدخول ← اضغط «تفعيل التنبيه الصوتي».
2. لوحة المدير ← الإعدادات ← رموز QR ← **إنشاء الرموز**.
3. اضغط 🔗 على بطاقة طاولة (أو امسحها بالموبايل) ← أضف وجبة ← يجب أن يظهر **«أرسل الطلب»**.
4. أرسل ← يصل الطلب لشاشة الطاقم مع صوت.

## الحماية من الطلبات الوهمية (جلسة الطاولة)

**المشكلة:** الزبون الذي مسح QR الطاولة يبقى الرابط عنده (سجل المتصفح، لقطة شاشة، رابط مُرسل لصديق). لو بقي `?t=4&k=…` يكفي للطلب، لاستطاع أي شخص إرسال طلبات من البيت في الليلة نفسها أو بعد أسبوع، فتصل للطاقم طلبات لطاولة جالس عليها زبون حقيقي.

**الحل (بدون أي خطوة إضافية على الزبون أو النادل):**

1. **مسح QR = فتح جلسة.** عند فتح رابط الطاولة يُنشئ الموبايل مستنداً في `sessions/{id}` فيه `{ table, k, phone, createdAt }`، والقواعد لا تقبله إلا إذا كان `k` مطابقاً لمفتاح الطاولة. بعدها يُحذف `k` من شريط العنوان فوراً، ويحفظ الموبايل رقم الجلسة عنده.
2. **كل طلب يحمل رقم الجلسة ورقم الموبايل** (`sid`, `phone`) بدل المفتاح. القواعد تقبل الطلب فقط إذا:
   - الجلسة موجودة ولنفس الطاولة ونفس الموبايل، ومفتاح الطاولة لم يتغيّر منذ فتحها؛
   - عمرها أقل من **مدة الجلسة** (من صفحة الإعداد، الافتراضي 4 ساعات، 1–24)؛
   - فُتحت **بعد آخر «تم الدفع»** على الطاولة (`tables/{رقم}.since`)؛
   - والموبايل غير محظور على هذه الطاولة (`blocks/{طاولة_موبايل}`).
3. **«تم الدفع» ينهي كل جلسات الطاولة** (يكتب `since` = الآن). من يفتح الرابط بعدها من البيت لا يستطيع الطلب؛ تبقى القائمة للتصفح ويظهر له: «انتهت جلسة طاولتك. امسح رمز QR…». الزبون الحقيقي التالي يمسح الرمز فتُفتح جلسة جديدة تلقائياً.
4. **رقم الموبايل** (`phone`): رقم عشوائي يحفظه المتصفح **يوماً واحداً** ويتجدد مع كل مسح، فمسح الرمز مرة ثانية من نفس الموبايل لا يُحسب موبايلاً جديداً.
5. **تنبيه الطاقم:** إذا وصلت طلبات لطاولة من **أكثر من موبايل** منذ آخر «تم الدفع»، تصير كل بطاقاتها **حمراء** وعليها رقم الموبايل (1، 2…)، والجديدة **تومض** حتى يستلمها أحد. في الحالة العادية (موبايل واحد) لا يظهر شيء من هذا. الطاولة التي يطلب منها أصدقاء بموبايلين تظهر حمراء أيضاً — النادل يرى ذلك بعينه ويتابع عادي.
6. **«رفض»:** على أي بطاقة غير مدفوعة. يجعل كل طلبات ذلك الموبايل غير المدفوعة على الطاولة `type: 'void'` (تختفي من شاشة الطاقم والسجل وطلبات اليوم)، ويكتب حظراً لهذا الموبايل على هذه الطاولة **3 ساعات**. الزبون المرفوض يرى «رفض المطعم أحد طلباتك…»، وإن حاول ثانية: «لا يمكن إرسال طلبات من هذا الجهاز…».

**ما الذي لا يحميه:** شخص في البيت لديه رابط قديم **ومسح** الرمز خلال آخر جلسة لم تُدفع بعد يستطيع الطلب حتى «تم الدفع» أو انتهاء المدة — لكن طلبه يظهر **أحمر برقم موبايل مختلف**، و«رفض» يحذفه ويمنعه. حظر «الرفض» مربوط برقم الموبايل (لا يوجد عنوان IP في Firebase)، فمسح بيانات المتصفح يتجاوزه، لكنه يحتاج QR صالحاً من جديد.

**الكلفة على Firebase:** مسح QR = كتابة واحدة + قراءتان (من القواعد)؛ كل طلب = ~3 قراءات إضافية من القواعد. بحدود 2–4٪ من الحصة المجانية لمطعم عادي.

## حسابات الطاقم واستلام الطلبات

- **حساب المدير** = الحساب الذي أُنشئ في Firebase Authentication وكُتب إيميله في صفحة الإعداد. يدخل شاشة الطاقم **بدون اسم مستخدم**، ويدخل به صاحب المطعم لطلبات اليوم ورموز QR وحسابات الطاقم، ويستطيع الضغط على أي طلب.
- **حسابات النُدُل:** لوحة المدير ← الإعدادات ← **حسابات الطاقم** ← الاسم الظاهر + اسم مستخدم (إنجليزي) + كلمة سر (6 أحرف على الأقل). يُنشأ لكل نادل حساب Firebase خاص (`اسم-رمز@PROJECT.firebaseapp.com`)، ويُحفظ:
  - `staff/{uid}` — `name`, `username`, `email` (قائمة الطاقم؛ الحذف منها يُخرج النادل فوراً)؛
  - `logins/{username}` — `email` (ليدخل النادل باسم المستخدم فقط).
- **كلمة سر جديدة لنادل:** يُنشأ له حساب جديد بنفس اسم المستخدم ويُحذف القديم من القائمة (لا يمكن تغيير كلمة سر مستخدم آخر من صفحة ثابتة بدون خادم).
- **الاستلام:** أول ضغطة «بدء التحضير» / «تم» / «تم الدفع» تكتب `claimedBy` (uid) و`claimedName` على الطلب. القواعد ترفض أي تعديل على طلب استلمه زميل — حتى لو تجاوز أحد الواجهة — ما عدا: المدير، و«تم الدفع» للطاولة (يعلّم كل طلباتها مدفوعة)، و«رفض».
- إذا ضغط نادلان بنفس اللحظة: يُقبل الأول، والثاني يرى «استلمه زميل قبلك».
- الطاقم القديم الذي كان يدخل بكلمة سر الطاقم المشتركة يستمر بالدخول نفسه (اسم مستخدم فارغ) — لكن بدون قفل ولا «طلباتي» حتى يُعطى كل نادل حسابه.

## الأمان
| الجزء | الحماية |
|---|---|
| GitHub token | Fine-grained، على مستودع واحد وصلاحية الملفات فقط · مشفّر في `data/auth.json` بـ PBKDF2 (مليون دورة) + AES-256-GCM · كلمة سر صاحب المطعم 10 أحرف على الأقل مع أرقام |
| أسوأ حالة | تعديل المنيو فقط، ويُسترجع أي إصدار من سجل git |
| الطلبات | قواعد Firestore: الزبون يُنشئ طلباً فقط ضمن جلسة طاولة مفتوحة وغير محظور، ولا يقرأ إلا طلبه بمعرّفه · القراءة لحساب المدير وحسابات `staff` فقط · تعديل طلب استلمه زميل مرفوض |
| الأسعار | السعر الذي يرسله موبايل الزبون لا يُعتمد: شاشة الطاقم وتقارير اللوحة تعيد حساب كل طلب من `data/menu.json` (رقم الوجبة + الحجم). إن اختلف السعر المرسل تظهر على البطاقة علامة ⚠ والمجموع المعتمد هو مجموع القائمة |
| إلغاء الوصول | احذف الـ token من GitHub · احذف النادل من «حسابات الطاقم» · أو غيّر مستخدم المدير في Firebase |
| الدفع | يدوي (كاش/طلب الحساب). الدفع الإلكتروني الموثّق يحتاج مفتاحاً سرياً لا يجوز وضعه في صفحة ثابتة — يتطلب خادماً صغيراً لاحقاً |

> `apiKey` الخاص بـ Firebase ليس سراً — الحماية في قواعد Firestore.

## التجربة محلياً (WAMP)
- افتح عبر الخادم: `http://localhost/laravel/myapp/restaurant/` — **وليس** بفتح الملف مباشرة (`C:/…/index.html`)، لأن المتصفح يمنع تحميل الملفات عندها.
- قبل الربط بـ GitHub: اللوحة وصفحة الإعداد تحفظان في المتصفح فقط، وتظهر التعديلات في المنيو على نفس الجهاز.
- Firebase يعمل من `localhost` أيضاً.

### ⚠️ رفع تعديلات الكود بعد النشر
الموقع نفسه يعمل commits (حفظ ونشر، تعديلات صاحب المطعم)، لذلك **احفظ تعديلاتك بـ commit أولاً، ثم اجلب تعديلات GitHub، ثم ارفع**:
```
cd C:\wamp64\www\laravel\myapp\restaurant
git add .
git commit -m "وصف التعديل"
git pull --rebase
git push
```
- إذا ظهر `rejected (fetch first)` فأنت نسيت `git pull --rebase`.
- إذا ظهر `cannot pull with rebase: You have unstaged changes` فأنت نسيت `git add` و`git commit` قبله.
- إذا ظهر **conflict** توقّف ولا تكمل قبل حلّه.
- تحذيرات `LF will be replaced by CRLF` عادية وتُتجاهل.

## الحدود المجانية
| الخدمة | الحد المجاني التقريبي | ملاحظة |
|---|---|---|
| GitHub Pages | حجم الموقع حتى 1GB | 200 وجبة بصور مضغوطة ≈ 20–30MB |
| Firestore (Spark) | 50K قراءة · 20K كتابة يومياً · 1GB تخزين | الحد لكل مشروع، أي لكل مطعم |
| Firebase Auth | Email/Password مجاني | تسجيل الدخول بالجوال (SMS) غير متاح على Spark |

عند تجاوز حد Firestore اليومي تتوقف الطلبات حتى اليوم التالي بدون أي رسوم (المنيو يبقى يعمل).

## مشاكل شائعة وحلولها

| المشكلة | الحل |
|---|---|
| الصفحة بيضاء أو عالقة على التحميل محلياً | افتحها عبر `http://localhost/...` وليس كملف |
| التعديل لا يظهر للزبائن | انتظر دقيقة · تحقّق من Actions/Pages في المستودع · حدّث بـ Ctrl+F5 |
| «كلمة السر غير صحيحة» في اللوحة | تأكد من كلمة سر صاحب المطعم · يمكن تعيين جديدة من صفحة الإعداد (مع الـ token) |
| «تعذّر الحفظ: 401/403» | انتهت صلاحية الـ token أو صلاحياته ناقصة ← أنشئ token جديداً وانشر من صفحة الإعداد مع كلمة سر جديدة |
| «تعذّر الإرسال» عند الزبون | القواعد لم تُنشر في Firestore (أو نُشرت قبل آخر تحديث للكود) ← انسخها من صفحة الإعداد وانشرها |
| «رمز QR هذا قديم أو غير صحيح» | البطاقة مطبوعة قبل تفعيل Firebase أو المفتاح تغيّر ← أعد «إنشاء الرموز» والطباعة · **أو القواعد القديمة ما زالت منشورة** (لا تعرف `sessions`) |
| «انتهت جلسة طاولتك» | طبيعي بعد «تم الدفع» أو بعد مدة الجلسة ← امسح QR من جديد |
| النادل يرى «استلمه زميل قبلك» | زميله ضغط أولاً ← البطاقة تُظهر «مع …» |
| حساب نادل: «اسم المستخدم مستخدم» | اختر اسماً آخر، أو استخدم «كلمة سر جديدة» للحساب الموجود |
| «تم تأكيد طلبك» لكن لم يصل شيء للطاقم | الرابط بدون `k` (رابط عام أو `?t=4` مكتوب يدوياً) ← استخدم رابط البطاقة من «إنشاء الرموز» (زر 🔗 أو مسح QR) |
| صفحة 404 عند كتابة رابط طاولة | نسيت `?` قبل `t` — الصحيح `/REPO/?t=4&k=…` |
| «انقطع الاتصال» في شاشة الطاقم | تعيد الاتصال تلقائياً خلال ثوانٍ (وفور عودة الإنترنت)، والطلبات التي وصلت أثناء الانقطاع تظهر مع تنبيه ← لا حاجة للتحديث |
| شاشة الطاقم لا تُصدر صوتاً | اضغط «تفعيل التنبيه الصوتي» وتأكد أن زر الصوت ليس مكتوماً |
| `permission-denied` في الطاقم | إيميل الطاقم في القواعد يختلف عن إيميل الحساب ← انسخ القواعد من صفحة الإعداد وانشرها |
| `git push` مرفوض | `git add .` ← `git commit` ← `git pull --rebase` ← `git push` |
| «Failed to fetch» في اختبار الاتصال | انقطاع إنترنت أو إضافة في المتصفح تحجب `api.github.com` ← جرّب نافذة خفية |
| «GitHub رفض الرمز (401)» في صفحة الإعداد | الـ token منسوخ ناقصاً، أو محذوف/مُعاد توليده، أو عبّأ المتصفح الخانة بكلمة سر محفوظة ← امسح الخانة والصق token صالحاً |
| «لا يملك صلاحية الكتابة (403)» | الـ token لا يشمل هذا المستودع أو Contents ليست Read and write ← عدّل الـ token في GitHub (Repository access + Contents) |
| «كلمة السر صحيحة لكن رمز GitHub لم يعد صالحاً» عند دخول المدير | تغيّر الـ token ← صفحة الإعداد ← الـ token الجديد + كلمة سر صاحب المطعم ← حفظ ونشر |
| اخترت ثيماً/نمطاً ولم يتغيّر شيء | الحفظ تم بدون token (لم يُحفظ) أو لم تمرّ دقيقة ← احفظ بالـ token وحدّث بـ Ctrl+F5 |
