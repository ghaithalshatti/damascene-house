# 🍽️ QR Menu — منيو إلكتروني للمطاعم بدون باك اند

قالب جاهز لمنيو مطعم يُفتح بمسح رمز QR على الطاولة. موقع ثابت (HTML + CSS + JavaScript) يُستضاف **مجاناً** على **GitHub Pages**،
مع لوحة إدارة لصاحب المطعم، و**طلبات مباشرة اختيارية** عبر **Firebase** (خطة Spark المجانية)، بدون أي سيرفر أو تكلفة استضافة.

القالب عام: لكل مطعم نسخة مستقلة من هذا المستودع بإعداداته وهويته الخاصة.

## الميزات

**للزبون (المنيو)**
- عربي فصحى + إنكليزي (أو لغة واحدة)، مع اتجاه RTL/LTR تلقائي.
- تصميم متجاوب لكل الشاشات: من الموبايل الصغير (320px) حتى الشاشات الكبيرة (قائمة الأصناف تصبح شريطاً جانبياً).
- 12 ثيماً احترافياً بتدرجات لونية + 4 أنماط تصميم (كلاسيكي / زجاجي / تطبيق موبايل / مجلة فاخرة)، يُختار منها في صفحة الإعداد.
- بحث ذكي يتجاهل الهمزات والتشكيل، تبويبات أصناف تتبع التمرير.
- تفاصيل الوجبة: صورة، وصف، أحجام بأسعار مختلفة، وسوم (الأكثر طلباً، جديد، حار، نباتي).
- سلة طلب: كميات، ملاحظة لكل وجبة («بدون بصل»)، تعديل وحذف.
- **بدون Firebase:** زر «اعرض الطلب على النادل» يعرض شاشة واضحة برقم الطاولة.
- **مع Firebase:** «أرسل الطلب» + «نادِ النادل» + «اطلب الحساب»، ومتابعة حالة الطلب (تم الاستلام ← قيد التحضير ← جاهز).
- الوجبات غير المتوفرة تختفي تلقائياً.

**لصاحب المطعم (لوحة الإدارة)**
- دخول بكلمة سر واحدة، يعمل من الموبايل.
- إضافة وتعديل وحذف الوجبات والأصناف، ترتيب بالسحب، إخفاء/إظهار بكبسة.
- رفع صور تُضغط تلقائياً (WebP).
- معلومات المطعم: الشعار، الغلاف، الهاتف، العنوان، الدوام، الخريطة، حسابات التواصل.
- تبويب «طلبات اليوم»: عدد الطلبات، المبيعات، متوسط الطلب، الأكثر طلباً، الطلبات حسب الساعة.
- رابط القائمة للمشاركة + مولّد رموز QR للطاولات + تغيير كلمة السر.
- كل حفظ يُنشر تلقائياً ويظهر للزبائن خلال دقيقة تقريباً.

**للطاقم (شاشة الطاقم)** — تتطلب Firebase
- استقبال لحظي للطلبات والنداءات وطلبات الحساب على أكثر من جهاز معاً.
- تنبيه صوتي واهتزاز، عدّاد في عنوان التبويب، الشاشة لا تنطفئ.
- فلاتر (طلبات / نداءات / حساب)، حالات الطلب، و«تم الدفع» مع حساب مجموع الطاولة.

## الصفحات والروابط

| الصفحة | الرابط | لمن |
|---|---|---|
| المنيو | `/` | الزبون (رمز QR عام، فيسبوك، خرائط Google…) |
| منيو طاولة | `/?t=5&k=xxxx` | الزبون عبر QR الطاولة |
| لوحة الإدارة | `/admin/` | صاحب المطعم |
| شاشة الطاقم | `/staff/` | النادل / المطبخ / الكاشير |
| الإعداد | `/setup/` | المطوّر فقط |

**معاملات الرابط:**

| المعامل | المعنى |
|---|---|
| `t=5` | رقم الطاولة (يظهر في المنيو وعلى الطلب) |
| `k=xxxx` | مفتاح الطاولة السري (يمنع الطلبات الوهمية؛ يُضاف تلقائياً عند توليد QR مع Firebase) |
| `preview=1&skin=cafe&primary=%23C0392B&style=glass` | معاينة ثيم/لون/نمط دون تغيير الإعدادات (للعرض على صاحب المطعم) |

أسماء الثيمات لـ `skin`: `classic` · `midnight` · `fresh` · `minimal` · `street` · `cafe` · `ocean` · `heritage` · `ember` · `rose` · `olive` · `royal`
ونمط التصميم بـ `style`: `classic` · `glass` · `app` · `magazine` (مثلاً `&style=magazine`)

## كيف يعمل بدون باك اند

```
الزبون ──قراءة──▶ GitHub Pages (index.html + data/*.json + images/)
صاحب المطعم ──حفظ──▶ GitHub API (commit مباشر على المستودع) ──▶ Pages يعيد النشر (~1 دقيقة)
الزبون ──طلب/نداء──▶ Firebase Firestore ◀──لحظياً── شاشة الطاقم
```

- **المنيو والإعدادات** ملفات JSON داخل المستودع. لوحة الإدارة تعدّلها عبر GitHub API بـ commit واحد لكل حفظ.
- **الطلبات** فقط تمر عبر Firestore (لأن GitHub Pages لا يستقبل بيانات من الزبائن).
- لا يوجد أي سيرفر، ولا اعتماد على CDN خارجي (الخطوط والمكتبات محلية).

## تجهيز مطعم جديد خطوة بخطوة

> الترتيب مهم: **GitHub ← Firebase ← صفحة الإعداد ← طباعة QR**

### 1) GitHub: رفع الكود
1. أنشئ مستودعاً **Public** فارغاً (بدون README) باسم المطعم، مثلاً `damascene-house`.
   أو من هذا المستودع: **Use this template ← Create a new repository**.
2. إذا رفعت يدوياً:
   ```bash
   cd restaurant
   git init
   git add .
   git commit -m "init"
   git branch -M main
   git remote add origin https://github.com/USERNAME/REPO.git
   git push -u origin main
   ```

### 2) GitHub Pages: تشغيل الموقع
- المستودع ← **Settings ← Pages ← Build and deployment**
- Source: **Deploy from a branch** ← Branch: `main` ← Folder: `/ (root)` ← **Save**
- بعد دقيقة تقريباً: `https://USERNAME.github.io/REPO/`

### 3) GitHub Token: صلاحية الحفظ من الموقع
GitHub ← **Settings ← Developer settings ← Personal access tokens ← Fine-grained tokens ← Generate new token**
- **Repository access:** Only select repositories ← اختر مستودع المطعم فقط
- **Permissions ← Repository permissions ← Contents:** Read and write
- **Expiration:** مدة الاشتراك مع المطعم (مثلاً سنة)
- انسخ الـ token فوراً (`github_pat_…`) — يظهر مرة واحدة.

### 4) Firebase: الطلبات المباشرة (اختياري)
بدونها يعمل كل شيء ما عدا: إرسال الطلب، نداء النادل، طلب الحساب، شاشة الطاقم، وطلبات اليوم.

1. **console.firebase.google.com ← Create a project** (أوقف Google Analytics).
2. **Build ← Firestore Database ← Create database**
   - Location: **eur3 (Europe)** — لا يمكن تغييره لاحقاً
   - **Start in production mode**
3. **Build ← Authentication ← Get started**
   - Sign-in method ← **Email/Password** ← Enable ← Save
   - Users ← **Add user**: إيميل الطاقم + كلمة سر (مثلاً `staff@damascene.com`) — الإيميل لا يلزم أن يكون حقيقياً
   - Settings ← **Authorized domains ← Add domain**: `USERNAME.github.io`
4. **Firestore ← Rules**: الصق القواعد الجاهزة من صفحة الإعداد (قسم Firebase ← زر «نسخ») ← **Publish**
5. **Project settings ⚙️ ← Your apps ← Web `</>`** ← سجّل التطبيق (بدون Hosting) ← انسخ كتلة `firebaseConfig` كاملة.

> لا حاجة لبطاقة دفع ولا لرقم جوال. حساب Google واحد يكفي لكل المطاعم: **مشروع Firebase جديد لكل مطعم**.

### 5) صفحة الإعداد
افتح `https://USERNAME.github.io/REPO/setup/` (الرابط الحقيقي، وليس localhost) وعبّئ الأقسام (التفاصيل في القسم التالي) ثم **حفظ ونشر**.

### 6) رموز QR
في نفس الصفحة، قسم «رموز QR» ← **إنشاء الرموز** ← **طباعة** (أو تحميل PNG لكل طاولة).
اطبعها **بعد** تفعيل Firebase حتى تحمل مفاتيح الطاولات.

### 7) التسليم لصاحب المطعم
- رابط لوحة الإدارة `/admin/` + كلمة سر صاحب المطعم.
- رابط شاشة الطاقم `/staff/` + كلمة سر الطاقم.
- رابط المنيو للمشاركة على السوشال ميديا.

### 8) تجربة نهائية
افتح `/staff/` على جهاز ← ادخل ← «تفعيل التنبيه الصوتي» ← امسح QR طاولة بالموبايل ← أرسل طلباً ← يجب أن يصل فوراً مع صوت.

## صفحة الإعداد (`/setup/`) بالتفصيل

| # | القسم | ماذا تُدخل | ماذا يحدث |
|---|---|---|---|
| 1 | ربط GitHub | owner (اسم الحساب)، repo (اسم المستودع)، branch (`main`)، token | «اختبار الاتصال» يتحقق من صلاحية الكتابة ويحمّل الإعدادات الحالية من المستودع. لا يكتب شيئاً. |
| 2 | الثيم والألوان | نمط التصميم (4 أنماط) + أحد الثيمات الـ12 + لون العلامة | معاينة مباشرة بإطار موبايل تتحدث فوراً. |
| 3 | هوية المطعم | الاسم، العبارة التعريفية، الشعار، الغلاف | — |
| 4 | التفاصيل | اللغات (عربي+إنكليزي / عربي / إنكليزي)، اللغة الافتراضية، العملة، الهاتف، العنوان، الدوام | الحقول تُعرض حسب اللغات المختارة. |
| 5 | الميزات | تفعيل سلة الطلب للزبون | عند إيقافها يصبح المنيو للعرض فقط. |
| 6 | Firebase | الصق `firebaseConfig`، إيميل الطاقم، كلمة سر الطاقم | القواعد تُولَّد تلقائياً بإيميل الطاقم. «اختبار Firebase» يسجّل الدخول ويتأكد. **كلمة سر الطاقم لا تُحفظ.** |
| 7 | كلمة سر صاحب المطعم | 10 أحرف على الأقل، حروف وأرقام | إلزامية عند أول نشر. اتركها فارغة لاحقاً للإبقاء على الحالية. |
| 8 | القائمة الابتدائية | «ابدأ بقائمة فارغة» | يحذف البيانات التجريبية عند النشر. |
| 9 | رموز QR | عدد الطاولات، من طاولة/إلى طاولة، رمز عام | طباعة A4 أو PNG. |

**عند «حفظ ونشر»** يُنشأ commit واحد يحتوي:
- `data/config.json` — كل الإعدادات (بما فيها owner/repo وإعدادات Firebase العامة)
- `data/auth.json` — الـ token **مشفّراً** بكلمة سر صاحب المطعم
- `images/brand/…` — الشعار والغلاف إن وُجدا
- `data/menu.json` فارغ إذا اخترت «ابدأ بقائمة فارغة»

> صفحة الإعداد لا تحفظ الـ token. عند فتحها لاحقاً أدخله من جديد.
> زر الحفظ بدون token = «حفظ» محلي على المتصفح فقط (للتجربة قبل الرفع).

## دليل صاحب المطعم (`/admin/`)

| التبويب | الاستخدام |
|---|---|
| **الوجبات** | ➕ وجبة جديدة · اضغط الوجبة للتعديل · المفتاح الأخضر = متوفرة/مخفية · ⠿ اسحب للترتيب |
| **طلبات اليوم** | إحصاءات اليوم/أمس (يطلب كلمة سر الطاقم مرة واحدة على الجهاز) |
| **الأصناف** | إضافة/تعديل (اسم + أيقونة) · ترتيب بالسحب · لا يُحذف صنف فيه وجبات |
| **معلومات المطعم** | الهوية، التواصل، العنوان، الدوام، رابط الخريطة، السوشال ميديا |
| **الإعدادات** | تغيير كلمة السر · رابط القائمة للمشاركة · رموز QR للطاولات |

**في نافذة الوجبة:**
- **الأحجام:** «إضافة حجم» ← اسم الحجم + السعر لكل سطر (صغير/كبير، عادي/دبل). عند وجود أحجام يُقفل السعر الأساسي ويظهر للزبون «يبدأ من» أقل سعر. الحجم الأول هو الافتراضي.
- **الوسوم:** الأكثر طلباً · جديد · حار · نباتي.
- **الصورة:** تُصغّر وتُضغط تلقائياً قبل الرفع، والقديمة تُحذف عند الاستبدال.

كل حفظ = commit تلقائي. يرى صاحب المطعم التعديل فوراً في اللوحة، ويظهر للزبائن خلال دقيقة تقريباً.

## دليل الطاقم (`/staff/`)
- الدخول بكلمة سر الطاقم (الإيميل محفوظ في الإعدادات). يبقى الجهاز مسجّلاً.
- أول مرة بعد فتح الصفحة: اضغط «تفعيل التنبيه الصوتي» (المتصفحات تمنع الصوت قبل أول ضغطة).
- **طلب:** «بدء التحضير» ← «تم» — الزبون يرى الحالة عنده.
- **نداء نادل:** «تم» بعد الذهاب للطاولة.
- **طلب الحساب:** يظهر مجموع الطاولة ← «تم الدفع» يغلق طلبات الطاولة.
- الشاشة يجب أن تبقى **مفتوحة** على جهاز واحد على الأقل (تابلت الكاشير مثلاً) لاستقبال الطلبات.

**تغيير كلمة سر الطاقم:** Firebase ← Authentication ← Users ← احذف المستخدم وأضفه من جديد بنفس الإيميل وكلمة سر جديدة.

### نمط التصميم
فوق الثيم، يُختار **نمط التصميم** من صفحة الإعداد (قسم الثيم والألوان)، ويُطبَّق على كل الصفحات مع أي ثيم:

| النمط | الشكل |
|---|---|
| **كلاسيكي** (`classic`) | بطاقات صلبة وواضحة — التصميم الأصلي |
| **زجاجي عصري** (`glass`) | طبقات شفافة ضبابية فوق خلفية متدرجة من لون العلامة، رأس عائم بإطار زجاجي، شريط بحث وأصناف عائم، عناوين أقسام على شكل كبسولات، وأزرار بتدرج وتوهّج |
| **تطبيق موبايل** (`app`) | مثل تطبيقات التوصيل: بانر مختصر، بحث على شكل كبسولة، **الأصناف شريط تنقّل سفلي بأيقونات**، بطاقات عائمة بظلال ناعمة. في لوحة المدير والطاقم تصبح التبويبات شريطاً سفلياً. على الكمبيوتر يبقى الشريط الجانبي |
| **مجلة فاخرة** (`magazine`) | طابع تحريري راقٍ: غلاف طويل بعنوان ضخم بخط Amiri، فهرس أصناف نصّي بخط سفلي، عناوين أقسام كبيرة بخطوط فاصلة رفيعة، صور حادّة بلا إطارات، ومساحات واسعة |

يُحفظ في `config.json` ضمن `theme.style`. التأثير الضبابي الثقيل محصور بعناصر قليلة حتى يبقى المنيو سريعاً على الموبايلات الضعيفة.

## رموز QR والطاولات

### شكل رابط الطاولة
```
https://USERNAME.github.io/REPO/?t=4&k=Ab3xY9qZ
```
| الجزء | المعنى |
|---|---|
| `?` | بداية المعاملات — بدونها يعتبر GitHub أن `t=4` اسم صفحة فيظهر **404** |
| `t=4` | رقم الطاولة (يظهر في المنيو وعلى الطلب) |
| `k=Ab3xY9qZ` | **الرمز السري للطاولة** — بدونه يعمل المنيو لكن **لا يُرسل الطلب** |

### كيف يعمل الإرسال
- **رابط بدون `k`** (أو الرابط العام، أو `?t=4` مكتوب يدوياً): المنيو يعمل بوضع **«اعرض الطلب على النادل»** — الزبون يرتّب طلبه ويُريه للنادل على الشاشة، ولا يُرسل شيء إلى Firebase. ستظهر رسالة «تم تأكيد طلبك» لكن **لن يصل شيء لشاشة الطاقم**.
- **رابط فيه `t` و`k` صحيحان**: يظهر زر **«أرسل الطلب»** وتعمل أزرار «نادِ النادل» و«اطلب الحساب»، ويصل كل شيء لشاشة الطاقم فوراً.
- قواعد Firestore ترفض أي طلب مفتاحه لا يطابق المحفوظ للطاولة، فلا يستطيع أحد إرسال طلبات وهمية بكتابة `?t=4` من خارج المطعم.

### إنشاء الرموز السرية
- تُنشأ عند الضغط على **«إنشاء الرموز»** (في الإعدادات بلوحة المدير، أو في صفحة الإعداد)، وتُحفظ في Firestore في `tables/{رقم}`.
- إنشاؤها يحتاج **تسجيل دخول بحساب الطاقم**، لأن قراءة وكتابة `tables` مسموحة للطاقم فقط:
  - في **لوحة المدير**: إذا لم يكن الجهاز مسجّلاً بحساب الطاقم تظهر نافذة تطلب **كلمة سر الطاقم** مرة واحدة، ويبقى الجهاز مسجّلاً بعدها. إذا أُغلقت النافذة دون دخول **لا تُنشأ البطاقات** ولا يتغيّر شيء.
  - في **صفحة الإعداد**: تُستخدم كلمة سر الطاقم المكتوبة في قسم Firebase؛ إن كانت فارغة أو خاطئة تظهر رسالة خطأ ولا تُنشأ البطاقات.
  - إذا لم يكن Firebase مُعدّاً أصلاً: تُنشأ البطاقات **بدون `k`** (منيو للعرض + «اعرض الطلب على النادل»).
- **الرمز ثابت لا يتغيّر**: إعادة «إنشاء الرموز» تقرأ الرموز الموجودة ولا تغيّرها، فالبطاقات المطبوعة سابقاً تبقى صالحة. عند إضافة طاولات زِد العدد واختر النطاق (مثلاً من 11 إلى 12) لطباعة الجديدة فقط.

### أدوات البطاقة
- ⬇️ **تحميل PNG** للبطاقة.
- 🔗 **فتح رابط البطاقة** في تبويب جديد (الرابط الكامل مع `t` و`k`) — لتجربة الطلب من الكمبيوتر دون موبايل. لا يظهر في الطباعة.
- **بطاقة عامة** بدون رقم: للباب، الواجهة، الفيسبوك، خرائط Google — تعرض المنيو بدون إرسال طلبات.
- إذا تغيّر رابط الموقع (دومين جديد) يجب إعادة الطباعة.

### تجربة الطلب المباشر
1. افتح `/staff/` وسجّل الدخول ← اضغط «تفعيل التنبيه الصوتي».
2. لوحة المدير ← الإعدادات ← رموز QR ← **إنشاء الرموز**.
3. اضغط 🔗 على بطاقة طاولة (أو امسحها بالموبايل) ← أضف وجبة ← يجب أن يظهر **«أرسل الطلب»**.
4. أرسل ← يصل الطلب لشاشة الطاقم مع صوت.

## الأمان
| الجزء | الحماية |
|---|---|
| GitHub token | Fine-grained، على مستودع واحد وصلاحية الملفات فقط · مشفّر في `data/auth.json` بـ PBKDF2 (مليون دورة) + AES-256-GCM · كلمة سر صاحب المطعم 10 أحرف على الأقل مع أرقام |
| أسوأ حالة | تعديل المنيو فقط، ويُسترجع أي إصدار من سجل git |
| الطلبات | قواعد Firestore: الزبون يُنشئ طلباً فقط بمفتاح طاولة صحيح، ولا يقرأ إلا طلبه بمعرّفه · القراءة والتعديل لحساب الطاقم فقط (مقيّد بإيميله) |
| إلغاء الوصول | احذف الـ token من GitHub، أو غيّر مستخدم الطاقم في Firebase |
| الدفع | يدوي (كاش/طلب الحساب). الدفع الإلكتروني الموثّق يحتاج مفتاحاً سرياً لا يجوز وضعه في صفحة ثابتة — يتطلب خادماً صغيراً لاحقاً |

> `apiKey` الخاص بـ Firebase ليس سراً — الحماية في قواعد Firestore.

## التجربة محلياً (WAMP)
- افتح عبر الخادم: `http://localhost/laravel/myapp/restaurant/` — **وليس** بفتح الملف مباشرة (`C:/…/index.html`)، لأن المتصفح يمنع تحميل الملفات عندها.
- قبل الربط بـ GitHub: اللوحة وصفحة الإعداد تحفظان في المتصفح فقط، وتظهر التعديلات في المنيو على نفس الجهاز.
- Firebase يعمل من `localhost` أيضاً.

### ⚠️ مهم بعد الرفع
الموقع نفسه يعمل commits (حفظ ونشر، تعديلات صاحب المطعم). **قبل أي `git push` من جهازك نفّذ `git pull`** وإلا ستحدث تعارضات أو تُمسح تعديلات المطعم.

## الحدود المجانية
| الخدمة | الحد المجاني التقريبي | ملاحظة |
|---|---|---|
| GitHub Pages | حجم الموقع حتى 1GB | 200 وجبة بصور مضغوطة ≈ 20–30MB |
| Firestore (Spark) | 50K قراءة · 20K كتابة يومياً · 1GB تخزين | الحد لكل مشروع، أي لكل مطعم |
| Firebase Auth | Email/Password مجاني | تسجيل الدخول بالجوال (SMS) غير متاح على Spark |

عند تجاوز حد Firestore اليومي تتوقف الطلبات حتى اليوم التالي بدون أي رسوم (المنيو يبقى يعمل).

## مشاكل شائعة وحلولها

| المشكلة | الحل |
|---|---|
| الصفحة بيضاء أو عالقة على التحميل محلياً | افتحها عبر `http://localhost/...` وليس كملف |
| التعديل لا يظهر للزبائن | انتظر دقيقة · تحقّق من Actions/Pages في المستودع · حدّث بـ Ctrl+F5 |
| «كلمة السر غير صحيحة» في اللوحة | تأكد من كلمة سر صاحب المطعم · يمكن تعيين جديدة من صفحة الإعداد (مع الـ token) |
| «تعذّر الحفظ: 401/403» | انتهت صلاحية الـ token أو صلاحياته ناقصة ← أنشئ token جديداً وانشر من صفحة الإعداد مع كلمة سر جديدة |
| «تعذّر الإرسال» عند الزبون | QR قديم بدون مفتاح ← أعد توليد الرموز وطباعتها · أو القواعد لم تُنشر في Firestore |
| «تم تأكيد طلبك» لكن لم يصل شيء للطاقم | الرابط بدون `k` (رابط عام أو `?t=4` مكتوب يدوياً) ← استخدم رابط البطاقة من «إنشاء الرموز» (زر 🔗 أو مسح QR) |
| صفحة 404 عند كتابة رابط طاولة | نسيت `?` قبل `t` — الصحيح `/REPO/?t=4&k=…` |
| شاشة الطاقم لا تُصدر صوتاً | اضغط «تفعيل التنبيه الصوتي» وتأكد أن زر الصوت ليس مكتوماً |
| `permission-denied` في الطاقم | إيميل الطاقم في القواعد يختلف عن إيميل الحساب ← انسخ القواعد من صفحة الإعداد وانشرها |
| `git push` مرفوض | نفّذ `git pull` أولاً |
